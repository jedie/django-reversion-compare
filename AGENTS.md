## Project

`django-reversion-compare` is a Django app that adds a side-by-side comparison view to the Django admin for models
tracked by [django-reversion](https://github.com/etianen/django-reversion).

## Development Setup

This project uses `uv` for dependency management and a test Django project (`reversion_compare_project`) for
development and testing.

Bootstrap the environment (creates `.venv`, installs deps):
```bash
./manage.py
```

After bootstrap, use the project CLI:
```bash
.venv/bin/reversion_compare_project
```

## Commands

```bash
# Run tests
python -m coverage run

# Run a single test module
.venv/bin/reversion_compare_project test reversion_compare.tests.test_compare
```

## Architecture

### Main package: `reversion_compare/`

- **`admin.py`** — `CompareVersionAdmin` is the class users inherit; it combines `CompareMethodsMixin` and
  `BaseCompareVersionAdmin`. `BaseCompareVersionAdmin` extends django-reversion's `VersionAdmin`, wires up
  comparison URLs, and dispatches field comparison via method naming conventions:
  `compare_{field_name}` or `compare_{field_type}`.
- **`mixins.py`** — `CompareMixin` provides version queryset ordering, navigation resolution, and context
  building — shared by both the admin and CBVs. `CompareMethodsMixin` holds the field-type compare methods
  (e.g. `compare_ForeignKey`, `compare_DateTimeField`) extracted from the admin so CBV users can reuse them
  without pulling in the admin base class.
- **`views.py`** — `HistoryCompareDetailView(CompareMixin, CompareMethodsMixin, DetailView)` — non-admin CBV
  for comparing versions in regular (non-admin) views. Demo and URL wiring in
  `reversion_compare_project/views.py` and `reversion_compare_project/urls.py`.
- **`compare.py`** — `CompareObject` represents a single field value from one version. `CompareObjects` wraps
  a pair of `CompareObject` instances and drives the diff; this is what compare methods receive. Supports
  ForeignKey, M2M, datetime, decimal, and choice fields.
- **`helpers.py`** — `html_diff()` and related utilities generate HTML diff output using `diff-match-patch`.
- **`compare_raw.py`** — Low-level utilities for accessing raw reversion version data.
- **`forms.py`** — `SelectDiffForm` for the admin UI to select two versions to compare.
- **`context_processors.py`** — Provides `version_string` template variable with the installed package version.
- **`admin/`, `models/`, `views/`** — Empty placeholder directories, currently unused.

### Test/demo project: `reversion_compare_project/`

Contains test models (`Car`, `Person`, `Variant`, etc.), admin registrations, and Django settings. The test suite
lives in `reversion_compare/tests/` and uses snapshot HTML files (`*.snapshot.html`) — never edit these directly,
they are regenerated by running tests.

### Key design pattern

Field comparison is dispatched from `CompareVersionAdmin` (via `BaseCompareVersionAdmin`) in a priority order:
1. `compare_{field_name}` method on the admin class
2. `compare_{field_type}` method (e.g. `compare_CharField`)
3. Default generic comparison

This lets users override comparison rendering at any level of specificity.

Files matching `reversion_compare/tests/*.snapshot.html` are auto-generated. Run the affected test to regenerate
them after intentional HTML changes.
